## 2. The pipeline (experiments/011-subjects)

```
tiers-A/B/C.txt  (27x38 tokens D/M/L/S/W; drawn in make_targets*.py, budgets matched by its annealer; budget_v3.py = class counts)
  → pipeline/run_from_tiers_vN.py
       quantize  : 8-neighbourhood → merged transition classes + rotation (HOST = darker, lighter tie-break, junctions j)
       equalize  : nudges tiers (erode/dilate preferred) to cut per-class surplus
       roles     : edge roles fixed; surplus placed by per-pair policy (S edge / figure interior / ground interior / fallbacks); v4 adds chip sub-classes, v5 adds motif classes
       scenes    : metapuzzle roles-to-scenes (max-flow feasibility, annealing) → scenes.txt (identical histograms)
       render    : metapuzzle prototype --classes classes-vN.json (full) and classes-ink-vN.json (ink), --rotation quarter --border tray --cell 21
       metrics   : piece-level shared adjacencies (gate < 10%, stretch 0), scene metrics (difficulty indicators), connectors (mating classes, informational)
  → evaluation per docs/EVALUATION.md: blind recognition (ink first, then full), grid review, T9 visual ambiguity; results recorded as *.md in the experiment folder
```
Specs are generated by `pipeline/gen_classes_vN.py` (v9 = S–L pairs, v10 = chip sub-classes, v11 = motifs). The 005 folder holds the earlier placeholder pipeline (cat/boat/tree) and the texture/spec generators the 011 pipeline copies from.

## 3. How the work was organized (reproduce this)

- The session lead is an orchestrator: it does not read or edit code; it writes documentation and decisions, views rendered PNGs to judge results, and delegates everything else.
- Work is cut into small, fully specified tasks for Haiku agents (one module, one experiment step, one evaluation), with exact file paths, interfaces and a report format; nothing about token limits is mentioned to them. Creative design (grammar, subjects, motifs) goes to Opus agents. Sonnet is used for larger solver work. Sub-agents cannot spawn sub-agents here.
- Agents never commit; the lead commits each agent's files by explicit path after running the relevant tests (`python3 -m pytest -q`; currently 627 pass) and pushes to `claude/multi-solution-jigsaw-puzzle-hzrw5s`. Commit messages end with the Co-Authored-By and Claude-Session trailers used throughout.
- Every result is evaluated blind by a fresh agent that sees only the PNGs (never the subject names); evaluations are recorded in the experiment folder and summarized in docs/FINDINGS.md; decisions go to docs/DECISIONS.md; owner suggestions go to docs/IDEAS.md unless adopted.
- Concurrency: agents work in separate files/folders (new `-vN` suffixes) to avoid collisions; the lead checks `git status` before committing.
- The owner is hands-off: their steers so far are recorded in DECISIONS.md (lines first; unique solutions with few wrong local fits; shared adjacency relaxed to "not practically reusable"; square lattice; piece count free; tray border; image models as a rare reference channel: send prompts, they return images).
